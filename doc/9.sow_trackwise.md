# Statement of Work (SOW)
## TrackWise — Plataforma de Análisis Predictivo Musical


---

## 1. Descripción general del proyecto

TrackWise es una aplicación web de análisis predictivo musical orientada a productores musicales y melómanos. Permite analizar el potencial comercial de una canción mediante un modelo de machine learning desarrollado por el equipo, generando predicciones cuantitativas sobre su desempeño esperado en YouTube.

El sistema soporta dos modalidades de entrada según el rol del usuario: carga de archivo MP3 para productores musicales (cuenta de pago) e ingreso de link de YouTube para usuarios normales (versión gratuita). El proyecto abarca el ciclo completo de ingeniería de software — diseño, desarrollo, integración y despliegue — sobre infraestructura de nube privada institucional.

---

## 2. Objetivos

### Objetivo general
Desarrollar e implementar una plataforma web funcional que aplique técnicas de machine learning para predecir el desempeño comercial de canciones, desplegada en nube privada institucional y documentada en su totalidad.

### Objetivos específicos
- Diseñar e implementar un modelo de ML propio capaz de predecir cuatro métricas de desempeño en YouTube.
- Desarrollar un backend con API REST segura que exponga el servicio de predicción.
- Construir un frontend React con experiencia diferenciada por rol, accesible y responsive.
- Gestionar autenticación, sesiones y autorización mediante Keycloak.
- Implementar seguridad en todas las capas del sistema: cifrado TLS, JWT, manejo de secretos y validación de entradas.
- Diseñar la base de datos relacional en mínimo 3FN con justificación documentada.
- Desplegar la plataforma completa en nube privada con configuración de red documentada.
- Producir la documentación técnica completa del sistema.

## 3. Alcance del trabajo

### 3.1 Incluido en el alcance

| Módulo | Descripción |
|---|---|
| Análisis de audio | Carga de MP3 (Productor) e ingreso de link de YouTube (Usuario normal); extracción de características; predicción de 4 métricas |
| Historial | Registro y consulta de análisis previos por usuario |
| Gestión de usuarios | Registro, login, roles RBAC, manejo de sesiones JWT vía Keycloak |
| Seguridad | TLS/HTTPS, JWT RS256 en memoria, variables de entorno, validación de entradas, CORS |
| Base de datos | PostgreSQL, diseño en 3FN con justificación |
| UI/UX | Interfaz diferenciada por rol, responsive, accesible (WCAG 2.1 AA básico) |
| Motor de ML | Modelo propio entrenado con dataset construido sobre base externa; API interna FastAPI |
| Infraestructura | Nube privada institucional, 2 instancias frontend, Docker / docker-compose |
| Documentación | Todos los entregables listados en la sección 5 |

### 3.2 Excluido del alcance

- Pasarela de pagos o cobro en línea
- Aplicación móvil nativa (iOS / Android)
- Reentrenamiento automático del modelo en producción
- Integración con plataformas de streaming distintas a YouTube
- Panel de administración de la plataforma (superadmin)
- Auditoría de seguridad externa o pentesting formal
- Soporte multiidioma

## 7. Supuestos

- La nube privada institucional tiene capacidad de cómputo suficiente para la inferencia del modelo de ML.
- El equipo tiene acceso a la infraestructura de red para configurar VLANs, firewalls y rutas con salida a internet.
- Es posible gestionar certificados TLS dentro de la red privada institucional.
- El dataset base externo es de acceso académico libre y puede usarse sin restricciones legales.
- Keycloak puede desplegarse como contenedor en la misma nube privada.
- Los usuarios finales cuentan con archivos MP3 de calidad suficiente para la extracción de características de audio.

## 9. Criterios de aceptación

El proyecto se considera completado satisfactoriamente cuando:

- El sistema predice las cuatro métricas definidas con desempeño de modelo aceptable .
- Ambos flujos de usuario — MP3 y link de YouTube — funcionan de extremo a extremo en el entorno de producción desplegado.
- La autenticación con Keycloak opera correctamente para ambos roles, con sesiones que expiran y se renuevan.
- Toda la comunicación externa utiliza HTTPS con certificado válido.
- La base de datos está documentado con justificación.
- La plataforma opera con las dos instancias de frontend en redundancia.
- Toda la infraestructura es reproducible desde cero usando los archivos de configuración documentados.
- Se entregan todos los entregables listados en la sección 5.

## 10. Riesgos principales

| Riesgo | Probabilidad | Impacto | Mitigación |
|---|---|---|---|
| Rendimiento insuficiente del modelo de ML | Media | Alto | Evaluar múltiples algoritmos; ajustar métricas de éxito si el dataset es limitado |
| Limitaciones de la infraestructura institucional | Media | Alto | Validar capacidad de cómputo antes del despliegue; tener plan de contingencia con recursos reducidos |
| Integración compleja entre servicios (Keycloak, ML, backend, frontend) | Alta | Medio | Definir contratos de API desde el inicio; pruebas de integración continuas |
| Tiempo insuficiente para completar todos los entregables | Alta | Medio | Priorizar entregables Must sobre Should; documentar decisiones de alcance |
| Dataset con datos insuficientes o desbalanceados | Media | Alto | Aplicar técnicas de balanceo (oversampling, undersampling); documentar limitaciones del modelo |
